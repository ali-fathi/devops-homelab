# Argo CD App-of-Apps Bootstrap

## Purpose

`homelab-applications` is the root Argo CD Application for the homelab platform. It watches the Git directory containing the child Application manifests and keeps those Application objects synchronized in the `argocd` namespace.

```text
Git
  -> homelab-applications (root Application)
  -> child Application CRs
  -> monitoring, Loki, Alloy, applications, and configuration
```

This removes the need to manually apply every child Application after the root Application has been bootstrapped once.

## Files

```text
kubernetes/gitops/argocd/bootstrap/root-application.yaml
kubernetes/gitops/argocd/applications/*.yaml
```

The root Application watches:

```text
kubernetes/gitops/argocd/applications
```

The directory contains these child Applications:

```text
alloy
garmin
health-dashboard
loki
monitoring
observability-config
ring-health-tracker
```

The root Application is stored outside that directory in `bootstrap/`. This prevents it from managing itself and avoids a self-referential app-of-apps loop.

## Ownership

The root Application owns the child `Application` resources. The child Applications own their workload resources.

```text
Terraform
  -> homelab-platform AppProject

homelab-applications
  -> Application/monitoring
  -> Application/loki
  -> Application/alloy
  -> Application/observability-config
  -> Application/garmin
  -> Application/ring-health-tracker
  -> Application/health-dashboard

Child Applications
  -> Helm releases, ConfigMaps, Services, Secrets references, and workloads
```

Terraform must not manage the child Applications, and the root Application must not directly manage the workloads generated by child Applications.

## Safety settings

The root Application uses:

```yaml
automated:
  enabled: true
  prune: false
  selfHeal: true
```

`prune: false` is intentional. Removing a child Application file from Git will not immediately delete the live child Application or its workloads. This is safer while the platform is being migrated and while backup/restore procedures are still being proven.

The child Applications also use `prune: false`.

## First bootstrap

The root Application must be created once because no existing Application currently manages it. From the repository root, apply the bootstrap manifest:

```bash
kubectl apply -f kubernetes/gitops/argocd/bootstrap/root-application.yaml
```

After this one-time bootstrap, future changes to files in `kubernetes/gitops/argocd/applications/` are reconciled by `homelab-applications`.

Check the root Application:

```bash
argocd app get homelab-applications
```

Check the child Applications:

```bash
argocd app list
```

Expected child names:

```text
alloy
garmin
health-dashboard
loki
monitoring
observability-config
ring-health-tracker
```

## Normal workflow after bootstrap

1. Edit a child Application manifest in Git.
2. Run YAML and whitespace validation.
3. Commit and push to `main`.
4. Argo CD refreshes `homelab-applications`.
5. The root Application updates the child Application object.
6. The child Application reconciles its own workload.
7. Verify child health and workload health.

Example validation:

```bash
python3 -m yamllint kubernetes/gitops/argocd/bootstrap/root-application.yaml kubernetes/gitops/argocd/applications
```

```bash
git diff --check
```

Example refresh and status checks:

```bash
argocd app diff homelab-applications --hard-refresh --diff-exit-code 0
```

```bash
argocd app get homelab-applications
```

```bash
argocd app get monitoring
```

The `--hard-refresh` flag belongs to `argocd app diff` in the CLI version used by this homelab.

## What this root Application does not manage

It does not manage:

- The Terraform-owned `homelab-platform` AppProject
- Argo CD installation itself
- The Argo CD repository credential ExternalSecret
- Helm chart repositories
- Any workload manifest directly
- Terraform state or Azure resources

Those remain owned by their existing systems.

## Adding a new application

Create a new Application manifest in:

```text
kubernetes/gitops/argocd/applications/
```

The file must:

- Use `apiVersion: argoproj.io/v1alpha1`.
- Have `kind: Application`.
- Use `metadata.namespace: argocd`.
- Reference the `homelab-platform` project unless a deliberate project boundary is created.
- Use an allowed source repository.
- Use an allowed destination namespace.
- Define an explicit sync policy.

Then validate and push:

```bash
python3 -m yamllint kubernetes/gitops/argocd/applications/new-app.yaml && git diff --check
```

```bash
git add kubernetes/gitops/argocd/applications/new-app.yaml && git commit -m 'feat(gitops): add new application' && git push origin main
```

The root Application will discover the new file and create the child Application.

## Removing an application safely

Because pruning is disabled, deleting a child Application file from Git will not automatically delete its live resources. This is intentional.

Before removal:

1. Confirm the workload is no longer needed.
2. Back up stateful data.
3. Review the child Application and resource list.
4. Decide whether the Application CR and workloads should be deleted separately.
5. Remove the file through Git.
6. Delete or retain live resources explicitly according to the approved migration plan.

Never enable root-level pruning as a shortcut for cleanup.

## Troubleshooting

### Root Application is OutOfSync

Inspect the diff:

```bash
argocd app diff homelab-applications --hard-refresh --diff-exit-code 0
```

Common causes:

```text
A new or changed child Application file is not committed.
The root Application is still pointing at an old Git revision.
The repository cannot be authenticated.
The AppProject does not allow the Git source or argocd destination.
The child manifest has invalid YAML.
```

### Child Application is missing

Check that the file is directly under the applications directory:

```bash
find kubernetes/gitops/argocd/applications -maxdepth 1 -type f -name '*.yaml' -print
```

The root uses `recurse: false`, so files in nested directories are intentionally ignored.

### Child Application exists but cannot sync

The root Application only creates or updates the child Application. Inspect the child independently:

```bash
argocd app get <child-app>
```

```bash
argocd app diff <child-app> --hard-refresh --diff-exit-code 0
```

For monitoring, check AppProject permissions before investigating Pods:

```bash
kubectl get appproject homelab-platform -n argocd -o yaml
```

### Root Application was accidentally deleted

Re-bootstrap it from the committed manifest:

```bash
kubectl apply -f kubernetes/gitops/argocd/bootstrap/root-application.yaml
```

This does not delete child Applications because pruning is disabled.

```text

[ ] homelab-applications exists in namespace argocd.
[ ] Root Application source points to the applications directory.

[ ] prune remains false.
[ ] Terraform does not manage child Applications.
```
